# Cost weight review

Part of batch D3. Every lost point in a report is explained by a finding with a `cost` (see the scoring invariant in
`AGENTS.md`). This page lists those costs so they can be reviewed as a set, with a prompt for an LLM acting as a judge.

The repository does not call any LLM. A person pastes the prompt and the table into a judge of their choice, reads
the answer critically and records the outcome below. The judge's answer is advice, not a decision: a cost changes
only through a normal code change, with the tests in `tests/cost-balance.test.ts` and `tests/scoring.test.ts`, and an
`ENGINE_VERSION` bump.

Regenerate the table after any cost change (only the part between the markers is rewritten):

```bash
cd apps/web
node scripts/dump-costs.mjs
```

## Review prompt

Paste everything between the lines, followed by the cost table above.

---

You are reviewing the deduction weights of a CV readability checker. It does not predict hiring outcomes and does not
replicate any named applicant tracking system. It scores how well software can read a CV and lists fixes in order of
value.

How the score works:

- Five dimensions with fixed maxima: parseability 25, keywords 25, structure 20, impact 20, contact 10 (total 100).
- A dimension's score is its max minus the sum of the costs of its findings, clamped to [0, max]. Every lost point
  must be explained by a finding; nothing else changes a score.
- Severity (critical, high, medium, low) orders the fix list. Cost is the number of points the finding removes.
- "Charged on fixtures" shows what the engine actually deducted on its test documents; "not triggered" means none of
  the fixtures caused that finding.

Please review the table and answer in this structure:

1. Inconsistencies between severity and cost (for example a "low" finding that costs more than a "high" one in the
   same dimension), with the finding ids.
2. Findings whose cost looks too high or too low relative to how much the defect actually stops software or a
   recruiter from reading the CV. For each, give the current cost, a suggested cost and a one-sentence reason.
3. Dimensions where a few findings together can wipe out the dimension on a realistic CV, or where a serious defect
   costs too little to matter.
4. Double charging: two findings that describe the same underlying fact.
5. Anything you would not change, so the reviewer knows it was considered.

Constraints for your suggestions:

- Keep every dimension's maximum as it is.
- Do not suggest costs that depend on a named vendor's parser or on hiring outcomes.
- Costs are small integers; zero is allowed for advisory findings.
- Say when you are unsure. Do not invent facts about how specific applicant tracking systems behave.

---
