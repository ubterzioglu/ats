## Infrastructure, and the traps in it

Most of the night went into deployment rather than code. The facts worth not rediscovering:

- **Build Pack must be `Dockerfile`.** Coolify defaults to Nixpacks, which runs `next start`. This project
  builds with `output: "standalone"`, so the server to run is `.next/standalone/server.js`. On Nixpacks the
  container never comes up and the site returns 503 with no useful error. This cost hours.
- **The image needs `ENV HOSTNAME=0.0.0.0`.** Docker sets `HOSTNAME` to the container id and the standalone
  server binds to it, leaving the loopback healthcheck unanswerable.
- **`scripts/` must be copied into the deps stage.** `package.json` has a postinstall hook that runs
  `scripts/copy-pdf-worker.mjs`; without the directory, `npm ci` aborts and the image never builds.
- **Auto-deploy does not work.** Every deployment in Coolify's list is labelled `Manual`. Pushes reach GitHub
  reliably — verified repeatedly against the GitHub API — but nothing tells Coolify about them. The app was
  most likely added as a *public repository* rather than through the GitHub App, and only the GitHub App
  source registers a webhook automatically.
  - Fix A: Coolify → Sources → connect via GitHub App. Cleanest, matches the other sites.
  - Fix B: GitHub → repo → Settings → Webhooks → Add webhook, using the URL from Coolify's Webhooks tab.
  - Until then: push, then press **Redeploy**. Redeploy builds whatever is newest *at the moment you press
    it*, so a push made after pressing needs another press.
- The Coolify app was deleted and rebuilt once during the night. Domains, direction (`www` and non-`www`) and
  the Dockerfile build pack all had to be set again. **No environment variables are needed** — the holding
  page is unconditional in code and Supabase is not configured.

## Two defects found in the engine, not yet fixed

- **Phone detection has a verified false negative.** The pattern in `lib/scoring/contact.ts` uses `[\s./-]`
  as a separator, and `\s` matches newlines, so it runs across lines. A German address block with a postcode
  above a date line — `Berlin 10115` over `2019 - 2024 Acme GmbH` — matches `10115\n2019`, nine digits, and
  the missing-phone finding is suppressed on a CV that genuinely has no number. Confirmed by running the
  regex directly. Fix: match per line.
- **A spaced-out heading** such as `E X P E R I E N C E` fails the six-word cap in `looksLikeHeading`
  (`lib/scoring/sections.ts`). The resulting penalty is correct, but it is reported as a *missing* heading
  rather than a malformed one, so the fix text sends the reader somewhere useless.

Both are described with more context in `docs/ats-rules.md`.

One finding from the research affects shipped copy: the claim that ATS systems auto-reject resumes is not

resumes are rejected" figure traces to a 2012 vendor marketing claim with no study behind it. Our lowest band
in `lib/scoring/index.ts` reads *"Likely to be dropped or misread"*. "Misread" is defensible; **"dropped"
leans on the unsupported idea** and conflicts with the project's own rule against overselling.

## Conventions worth knowing before touching the code

- `lib/scoring/` is pure: no DOM, no network, no React, no I/O. One file per dimension.
- A dimension's score is `max - sum(costs)`, clamped. Never adjust a score directly; add a `FindingDraft`
  with a `cost`. `tests/scoring.test.ts` asserts the invariant and the UI depends on it.
- `lib/extract/` is browser-only. The CV never reaches the server — this promise is printed on the page, and
  any feature that would break it needs a product decision first.
- Run `npm run lint`, `npm run typecheck` and `npm test` after any change; all three must pass clean.
- Do not edit files while a build is running. Two concurrent `next build` runs corrupt `.next` and produce
  confusing `webpack-runtime` errors that look like real bugs. This happened twice tonight.
