### 2. An engine defect in date reading

`extractPeriods` in `lib/scoring/experience.ts` reads **no date range at all** when a word sits
immediately before the year separated only by whitespace. Probed directly:

| Line | Period read |
|---|---|
| `Senior QA Engineer, Acme GmbH, 2021 - present` | yes |
| `Senior QA Engineer    Acme GmbH    2021 - present` | **none** |
| `Senior QA Engineer    Acme    2021 - 2023` | **none** |
| `Senior QA Engineer 2021 - 2023` | **none** |

Cause: `RANGE_RX`'s left alternative `[\p{L}]+\.?\s+(?:19|20)\d{2}` exists for "Jan 2021". It
greedily matches `Engineer 2021`, `parseEndpoint` rejects it because "Engineer" is not a month
name, and the loop `continue`s — it never falls back to the bare-year alternative.

This is not cosmetic. Column-aligned entries are one of the commonest CV layouts, and in that
layout `stats.experienceMonths` is zero, the Structure dimension's date reading is blind, and the
`A.2` entries table is correctly but uselessly empty.

Fix direction: on a failed endpoint, retry the line against the remaining alternatives rather than
skipping it. `tests/bench-entries.test.ts` uses comma-separated fixtures today precisely because of
this; add column-aligned fixtures once it is fixed.

## File ownership, if more than one agent runs

The split that worked, and the one to keep:

| Area | Owns |
|---|---|
| `lib/scoring/**`, `types/analysis.ts`, `lib/ai/semantic-match.ts`, `lib/ai/embeddings.ts` | the engine agent (B, F, J) |
| `lib/pdf/**`, `lib/resume/**`, `types/resume.ts`, `public/fonts/**` | the builder agent (E) |
| `lib/ai/providers/**`, `lib/ai/tasks/**`, `lib/ai/schema.ts` | the AI-layer agent (L, D) |
| `app/**`, `components/**`, `lib/bench/**`, `lib/editor/**`, `lib/ui.ts`, `lib/theme.ts`, `globals.css`, `tailwind.config.ts`, `messages/*.json` | the interface agent (V, C, A, and the UI half of L and E) |

Two rules that earned their place:

- **`messages/*.json` has one owner.** An agent that needs copy lists the keys it wants in its
  commit message; the interface agent adds them. Three agents editing three catalogs that must stay
  key-identical is how they stop being key-identical.
- **Stage explicit paths, never `git add -A`.** Another agent's in-flight work was in the tree
  several times. `git add -A` would have committed it under the wrong message.

`package-lock.json` is the only file everyone touches. On a conflict, take the version from whoever
added the dependency and re-run `npm install`.

## Decisions already taken that constrain what is left

These were argued once and are recorded in commit trailers. They are not open questions.

1. **The engine's own wording stays English.** Findings, dimension labels and band names are
   composed in `lib/scoring/`. Translating them means giving that pure layer a locale, which it is
   forbidden to have, or emptying it of language. The interface is translated in three languages;
   the engine is not. Recorded under `P0.5` in `MASTERPLAN.md`.
2. **`live` cyan means AI-produced or AI-working, and nothing else.** Three files may paint with
   it, each because it renders model output. `tests/live-colour.test.ts` fails on a fourth. A new
   AI surface adds itself to `AI_SURFACES` with a reason.
3. **A view may never contradict the score.** The identity table takes its found/missing status
   from the engine's findings rather than detecting fields itself; the entries table calls the
   engine's `extractPeriods` rather than parsing dates itself. Two sources of truth would drift,
   and the drift would show as the product contradicting itself on screen.
4. **Empty stays empty.** The editor removes a cleared field rather than storing `""`, and removes
   a section when its last item goes. The one exception is a date, where JSON Resume writes `""`
   for a role that is still open — that is data.
5. **Drafts are produced on request, never on render.** Generating one per finding would force a
   model download, spend the consent on items nobody opens, and burn battery.
6. **A rule before a model.** `draftFix` reaches for a deterministic rewrite rule first and only
   asks a model when no rule applies. Instant, no download, cannot invent.
7. **Shared reports are rebuilt, not cast.** `restoreSharedReport` treats the stored row as
   untrusted input. Every new required field on `AnalysisResult` needs a default there, or old
   share links start disappearing.

## Conventions

- Run `npm run lint`, `npm run typecheck` and `npm test` from `apps/web` after every batch. All
  three clean, every time.
- One commit per batch. Conventional commit subject, a body that says why, then the trailers:
  `Constraint:`, `Rejected:`, `Confidence:`, `Scope-risk:`, `Directive:`, `Not-tested:`.
- `Not-tested:` is not a formality. Several things in this codebase are honestly unverified and say
  so; that is how the next person knows where to look.
- A new message key needs all three locales. `tests/messages.test.ts` enforces key parity, catches
  untranslated values, and checks ICU placeholders survive. Its verbatim exemptions are per locale
  on purpose.
