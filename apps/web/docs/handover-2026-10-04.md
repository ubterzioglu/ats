## 4. Decisions already taken. Not open questions.

Argued once, recorded in commit trailers, and binding on everything still to come.

1. **The engine's own wording stays English.** Findings, dimension labels and band names are composed
   in `lib/scoring/`. Translating them means giving that pure layer a locale, which it is forbidden
   to have. The interface is translated in three languages; the engine is not.
2. **`lib/ai` may never feed `lib/scoring`.** Similarity arrives as data or not at all.
   `tests/scoring-purity.test.ts` enforces it per file.
3. **The score runs in normalized mode only.** Strict and semantic are a comparison beside it.
4. **`live` cyan means AI-produced or AI-working, and nothing else.** A fourth file painting with it
   fails `tests/live-colour.test.ts`. A new AI surface adds itself to `AI_SURFACES` with a reason.
5. **A view may never contradict the score.** The identity table takes found/missing from the
   engine's findings; the entries table calls `extractPeriods`; `I.2` compares dates on
   engine-normalised months and terms through `countOccurrences`. Two sources of truth drift, and
   the drift shows as the product contradicting itself on screen.
6. **Empty stays empty.** The editor removes a cleared field rather than storing `""`, and removes a
   section when its last item goes. The one exception is a date, where JSON Resume writes `""` for
   an open role — that is data.
7. **Drafts are produced on request, never on render.** One per finding would force a model download,
   spend the consent on items nobody opens, and burn battery.
8. **A rule before a model.** `draftFix` reaches for a deterministic rewrite first and only asks a
   model when no rule applies. Instant, no download, cannot invent.
9. **Shared reports are rebuilt, not cast.** `restoreSharedReport` treats the stored row as untrusted
   input. Every new required field on `AnalysisResult` needs a default there, or old share links
   start disappearing.
10. **Nothing enters a CV unconfirmed.** `D.3` makes this a test, not a habit.
11. **A reader takes what it needs as an argument rather than deriving it a second time.** `F.1`'s
    `parseJobAd` receives the terms instead of classifying headings itself; `I.2` receives
    engine-normalised months instead of parsing dates. Two derivations of the same thing drift, and
    deriving in place is also how import cycles get built. This is decision 5 applied to the inside
    of the engine rather than to the views.

## 5. File ownership, if more than one agent runs

| Area | Owns |
|---|---|
| `lib/scoring/**`, `types/analysis.ts`, `lib/ai/semantic-match.ts`, `lib/ai/embeddings.ts` | engine agent (B, F, J) |
| `lib/pdf/**`, `lib/resume/**`, `lib/linkedin/**`, `types/resume.ts`, `public/fonts/**` | builder agent (E, I) |
| `lib/ai/providers/**`, `lib/ai/tasks/**`, `lib/ai/schema.ts` | AI-layer agent (L, D) |
| `lib/interview/**` | interview agent (H) |
| `app/**`, `components/**`, `lib/bench/**`, `lib/editor/**`, `lib/ui.ts`, `lib/theme.ts`, `globals.css`, `tailwind.config.ts`, `messages/*.json` | interface agent |

Three rules that earned their place:

- **`messages/*.json` has one owner at a time.** An agent that needs copy lists the keys in its commit
  message; the owner adds them. Three agents editing three catalogs that must stay key-identical is
  how they stop being key-identical. When no interface agent is running, hand the catalogs to
  whoever needs them — but to exactly one agent.
- **Stage explicit paths, never `git add -A`.** Another agent's in-flight work was in the tree
  several times this session, including a file that did not typecheck yet.
- **An agent may import from another lane, but never edit it.** Needed changes go in the commit
  message as a `Directive:`; the owner makes them. That is how both engine defects above were
  reported and fixed.

`package-lock.json` is the only file everyone touches. On a conflict, take the version from whoever
added the dependency and re-run `npm install`.

## 6. Conventions

- Run `npm run lint`, `npm run typecheck` and `npm test` from `apps/web` after every batch. All three
  clean, every time. **A batch is not done because its code is written; it is done when the gate is
  green.** One batch was ticked in `MASTERPLAN.md` while its file did not typecheck.
- One commit per batch. Conventional subject, a body that says why, then the trailers:
  `Constraint:`, `Rejected:`, `Confidence:`, `Scope-risk:`, `Directive:`, `Not-tested:`.
- **`Not-tested:` is not a formality.** Several things here are honestly unverified and say so; that
  is how the next person knows where to look.
- A new message key needs all three locales. `tests/messages.test.ts` enforces key parity, catches
  untranslated values, and checks ICU placeholders survive. Its verbatim exemptions are per locale on
  purpose.
- When a batch lands, tick its row in `MASTERPLAN.md`, update the counter in section 1, and delete
  its block from `agent-prompts.md` rather than leaving a stale prompt behind.
